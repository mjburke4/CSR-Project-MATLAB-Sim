# Shared Tranche 11 fixture specification

Authoritative inputs are `csr11/scenarios/replay/plan.json`, `cases.csv`, and `draws.csv`. Read the files rather than copying their values into independent implementations. No completed outcomes are encoded as inputs. Native reference generation determines observed trajectories; MATLAB comparison evaluates the complete corresponding trajectories.

## Execution

Run cases in input order: `ab`, `ba`, `slow`, `track`. Each stops at 8 simulated seconds. Construct nodes in order 1, 2, 3, with actual MAC and HOP objects. Node 1 is final application destination; nodes 2 and 3 each have four finite applications of 16 payload bytes and DSCP 0. Each source's candidate application ID is 1..4. The pair `(source, ID)` is the identity. Bare HOP wire profile, 128 kbps and +33 dBm apply to all DATA and ACK; native may use ConfigureLinkControl(128,128,33,33,6). The fixed radio inputs isolate scheduling and do not validate adaptive rate/power decisions. Retain real HOP ACK generation, flow window growth, pending/retry bookkeeping and MAC selection, holdoff, reservation countdown, aggregation and ACK repeat policy.

Duty cycling is disabled. All MACs initially have Search state and SYNC false. Active/reported nodes are 3; slot selection is historical modulo-probe with range 31 and reduction 0. Existing forced reservation overrides must be disabled. Known-neighbor state has last-heard time zero and reservation −1: gateway knows 2 and 3; each source knows gateway only. Set initial knowledge without delivering to HOP. Native initialization calls NoteHeardFrom twice only: default counters are already−1. Do not call NoteNeighborReservedSlot during initialization because that API starts SlotTick even for−1; MATLAB mac.receive metadata initialization does not start it. Do not prewarm or manually align recurring timers. Let public enqueue/state APIs arm normal local timing; source2/3 begin work at zero, while gateway begins MAC work at its first received DATA.

Schedule the optional `track` case's gateway Track transition at 0.25 s and Search transition at 0.65 s before scheduling any offered arrivals; neither event is on a 13 ms boundary and Track begins before the first source DATA. Other cases have no prescribed transitions. Transport does not change receiver state. This fixture deliberately permits controlled ingress regardless of receiver/transmitter state and models no collision/half-duplex loss. Its contention is MAC access and shared ACK service; it is not an RF contention benchmark.

Schedule a common offer poll at every exact integer multiple of 0.02 s, starting at zero and ending strictly before 8 s. Every poll invokes source 2 then source 3. It invokes the offer function **once** per source; never drain an entire free capacity window in one invocation. Offers cease for a source once four applications have been admitted, though a generic HOP wake may still be recorded. Native/MATLAB admission attempts must leave the same source demand state after blocked offers.

The offer function returns without emitting events when all four apps are already admitted. Otherwise emit `offer` with the next candidate ID and the current pre-call snapshot; call actual HOP canSend/CanSendToHop. If blocked, emit `blocked` and retain the candidate. If allowed, invoke real HOP send, assign the application generation time to that successful admission, increment that source's admitted total, and emit `admit` with the post-call snapshot. A native SendData void result is admitted only after canSend allowed and the real pending/resend insertion occurs; do not count it by assumption if enqueue can fail.

The actual HOP wake callback emits `wake` then invokes that same source offer function synchronously. Do not add a new driver timer or loop. Preserve the production one-TIC callback timing; native rounds to its time resolution. Source NSDP-release callbacks only observe state; they must not trigger admission directly. No production NWK objects are involved, so the statement established by these fixtures is real **HOP admission** under a synthetic driver.

## Raw tape

`draws.csv` has exact columns `case,node,ordinal,min,max,draw`. There are 128 entries per node and case. `ordinal` is 1-based per node, including initial preparation and every advertised reservation selection. Nodes2/3 alternate draws3,7 and9,1 in `ab`, `slow`, `track`; `ba` exchanges those tapes. Gateway draws1 in all cases except `slow`, where it draws28. These are raw values before reservation avoidance, not final counters.

Every consumed tape entry must match request node/ordinal/support. Fail on exhaustion, wrong bounds, noninteger/out-of-bounds values, repeated or skipped input ordinals, unsupported subsystem or unsupported shape. Record consumed counts and explicit unused suffix counts for all three nodes, including zero-consumption nodes if any. Reference matching requires the same entire consumed trace and count; equal consumed common prefixes alone do not pass.

## Controlled transport and emitted frames

Hook actual MAC transmission, preserving actual source-computed airtime and actual emitted wire envelopes/segments. The native device should have no connected real peers; its normal TX function may compute duration/state without producing RF receptions. A test-only observer forwards copies of actual transmitted segments to their addressed destination at `TX start + actual duration + 1 microsecond`. Schedule these arrivals in segment order during TX-start processing. MATLAB schedules its normal finish event after its Transmit callback; the propagation delay ensures those TX-finish callbacks execute before ingress. Do not synthesize expected successful feedback: receiver HOP must generate ACK and receiver MAC must service it.

No overhearing is delivered. On each addressed ingress, log `ingress_before`, update the destination MAC's heard-neighbor and advertised reservation through its public ingress/observation APIs, and invoke actual HOP ReceiveFromMac/receive. For native, `DeliverRxFrameToUp` only calls its callback, so the transport driver must perform the MAC heard/reservation observation as well. Preserve frame kind, original source/ID, sequence and ACK bitmap metadata. Use fixed pathloss70 dB and SNR20 dB for HOP observations. Update reported active nodes from the emitted envelope if applicable. Log `ingress_after` only when both MAC observation and HOP processing finish, including release/cancel work. Do not trigger fake receiver Search/Track transitions as part of successful delivery.

HOP owns sent notifications: native SetMac installs its TxSent callback; MATLAB `Sent` invokes hop.notifySent on actual emitted frames. Do not replace that callback merely to add an observer.

## Event CSV

Use `plan.json.events_schema` exactly, with one header and rows across all four cases. Reset `order` to 1 for each case. It is the ordinal of the listed semantic events, not every internal production trace. Every row includes a snapshot of the row's node and peer immediately at the semantic emission point. MAC states are Idle0/Search1/Track2/Tx3. Boolean `prep` is0/1. Counter/opportunity/advertised use their real negative sentinels. `admitted` is cumulative synthetic-driver admissions for that node (gateway0). Unavailable nonidentity quantities use0. `app_source`, `app_id`, `hop_seq`, `ack_bits`, `dack_bits` use0 when absent; DATA is identified by nonzero app_source/app_id, ACK by its actual sequence/window with app_source/app_id0. Store bitmaps losslessly as integer decimal values. `time_ns` is rounded integer nanoseconds; allow at most1 ns paired timing deviation and report it explicitly.

- `offer`: pre-admission snapshot, source node, peer1, next candidate identity; hop_seq0 until assigned.
- `admit`/`blocked`: post-decision snapshot; admitted DATA has actual HOP sequence; blocked hop_seq0. No frame rate/duration requirement on offer/blocked rows: radio fields0; admit uses128/+33.
- `tx_start`: one row per actual emitted segment, in selected order, at the native/MATLAB transmit callback before selected queue mutation and sent notifications. Node is transmitting radio, peer is segment destination; actual segment type, app identity/sequence/ACK windows, actual aggregate rate/power are populated. Every segment in one aggregate uses the same MAC snapshot. Opportunity/advertised distinguish consumed and next reservations.
- `ingress_before`/`ingress_after`: receiving node, peer is actual transmitter; use received frame metadata. Radio fields are actual received envelope rate/power. All segments from an aggregate carry its advertised reservation.
- `release`: emitted inside real HOP NSDP release callback; source radio, peer1, app_source is the original source from the callback; app_id/hop_seq/bitmap fields0, radio0. Keep app_id/hop_seq0 in both implementations because native callback exposes original source/destination but not a unique completed sequence. Snapshot here distinguishes capacity release from later resend/MAC removal.
- `wake`: inside real HOP queue wake callback before synthetic offer; source node, peer1; identity0/radio0. Gateway generic wake, if any, uses peer0 and unavailable peer-specific fields0.
- `busy`: after prescribed receiver state change; gateway node, peer0, identity0; fields without a peer are0.
- `final`: at horizon8 after all earlier events and before simulator disposal, emit gateway peer0, source2 peer1, source3 peer1 in that order; identity0, radio0. Do not mutate state to drain queues.

When peer is0, set neighbor_outstanding/neighbor_threshold0; MAC snapshot and hop_pending/resend_queue remain meaningful. When peer is real, query real HOP admission snapshot even if no outgoing flow exists; untouched peer entries have outstanding0,threshold0.

`draws.csv` OUTPUT is different from input: `case,node,ordinal,time_ns,min,max,draw,resolved,purpose`. `resolved` is the final slot after production occupancy probing. `purpose` is prepare or advertise. MATLAB annotates through existing mac_prepare/Transmit callbacks; no-new-draw preparation leaves prior resolved rows untouched. Native observes the return slot without bypassing the loop. Each consumed raw draw must have exactly one resolved result and purpose before completion. `summary.json` records runtime, per-case delivery/admission/release/wake totals, per-node tape consumed/unused counts, event counts, source/input hashes, and exact comparison result once the native reference exists. Additional native detail is allowed as separate files; do not silently extend the common output schema.

If the native executable finds a mechanical API or event-boundary obstacle, report it before changing this common specification. Diagnostic trajectory differences must remain visible; do not weaken reference comparison to make them disappear.
