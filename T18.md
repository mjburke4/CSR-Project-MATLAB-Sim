# Tranche 18: local and relayed service, admission and retries

This tranche investigates why node 5 admits and delivers more local traffic
than ns-3 while upstream traffic receives less service. It measures the
4 → 5 → 1 path using the existing real PHY, autonomous routing and default
continuous receive timing. Production MATLAB source is preserved.

## Install and run

Copy your validated Tranche 17 installation to a short folder, such as
`C:\csr18`. Extract every file in `t18up.zip` directly over that copied root.
The update requires the exact T17 installation that passed 660 tests and the
campus run; the older public checkpoint alone is insufficient.

Start a fresh MATLAB session in the new installation root and run:

```matlab
clear functions
report = run_tranche18_validation;
```

The runner performs a new preflight, executes the diagnostics and observer
control, then runs the retained subsystem tests. It prints progress and
packages the evidence as `t18.zip`. Return the printed ZIP path for review.
If a case fails, preserve its partial evidence and return the available ZIP.
Do not alter source or reference files to make an identity check pass.

There are eleven simulations totaling 6,900 simulated seconds. Their
wall-clock time depends on the workload and export costs; the runner prints
an estimate from completed cases. Most cases use three nodes. The final
900-second campus-prefix case retains all seven nodes.

All retain the original 300-second application start and 0.02-second offer
interval. Retained geometry, radio limits, PHY/ECC, historical profiles and
packet sizes are unchanged. The three-node cases remove other nodes and
interferers, so they are explicitly new isolation experiments. The campus
prefix retains the upstream node-7/8 traffic responsible for much of the
observed DACK pressure.

The observer-off control must reproduce the mixed seed-128 case's core
statistics and raw observations exactly. The campus prefix is compared with
T17 before 900 seconds. Its protocol and PHY prefix are fully comparable;
the T17 admission trace stops after 100,000 rows, so only that common prefix
can be checked against T17. T18 must retain all 180,000 prefix-case attempts.

## What the return will answer

Review separates node 5's local and relayed admissions, queue-to-HOP waits,
actual transmission waits, ACK/DACK releases and retries. It compares each
condition and seed with fresh pinned ns-3 observations. Packet lineage and
callback order identify cohorts; they do not expose every hidden queue-scan
decision or prove causal equivalence between independent random streams.

One previously accepted model difference remains explicit: MATLAB waits for
an actual MAC transmission before starting a queued retry's next timeout;
native ns-3 can time out a provisionally queued retry. This investigation does
not silently reverse that policy. Source review found no explicit local-DATA
priority over relayed DATA in either implementation.

Finite-stop pending work is reported without an added drain period. A case
with no DACK events is reported as such. All declared protocol, PHY, admission
and diagnostic traces must be complete; omitted records fail the gate.
