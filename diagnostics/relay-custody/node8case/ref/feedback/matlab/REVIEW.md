# MATLAB feedback signature review

The M owner run stops at 312.143 seconds, node 8 physical TX 74. Its only reported mismatch is `child1.kind`: the portable child is logical DACK (old signature value 2), while native MAC transmits outer ACK type 1 with both `is_ack=1` and `is_dack=1`. Sequence 30, destination 7, 41-byte size, rate/power/preamble, reservation, ACK window and both bitmaps already match. This is a signature representation error, not evidence for changing protocol behavior.

The portable source keeps the two roles distinct where needed. `csr.hop.Layer.makeAck` copies both receive-window bitmaps and changes `Kind` to DACK only when the current response grants DACK custody. `receiveFeedback` uses bitmap membership for window feedback, with ACK precedence on overlapping bits; both frame kinds enter the same branch. Exact ACK versus single DACK remains distinct in the non-window branch. `csr.mac.Layer.enqueue` puts ACK and DACK in the same queue and applies the same destination/window replacement rules. `Frames.acknowledgment` uses the same byte formula for both. The separate generated-ACK/DACK counters are diagnostic and remain untouched.

Native source independently confirms that feedback starts with logical type and two independent flags, then MAC writes outer ACK type whenever IsAck is true. Authentication restores logical DACK from its flag where needed. A nonzero historical DACK bitmap does not imply that the current feedback's IsDack flag is set.

Native type 2, a plain ACK standing in for a DACK, missing flag columns, invalid flag values, different maps/sequence/address/size and unrelated control kinds still fail.
