# Tranche 17: full portable regression and campus release gate

The next milestone is to establish how the reviewed Tranche 16 implementation
behaves over the original 6,000-second campus workload, with the complete
portable regression suite. The previous focused gate passed 129 MATLAB tests,
12 real-PHY cases and 192 structural checks. Continuous and optional nanosecond
timing produced the same delivery, retry, feedback and admission outcomes in
those cases. Continuous timing therefore remains the default.

## Install and run

Copy the exact working Tranche 16 installation to a short path, such as
`C:\csr17`. Extract every file in `t17up.zip` directly into that copied root,
allowing the included documentation and package inventory to be replaced.
This is an update for Tranche 16; the public Tranches 6–14 checkpoint alone is
not a sufficient base. Keep the working Tranche 16 installation available.

Start a fresh MATLAB session in the new installation root and run:

```matlab
clear functions
report = run_tranche17_validation;
```

The runner verifies the frozen source and references before running all
top-level portable tests, then the unchanged campus benchmark. It saves
`results/t17/t17.zip`. Return that ZIP for review.

The campus phase may take hours and is deliberately uninstrumented. It prints
its start time and prints again when simulation returns and export begins;
silence during simulation does not itself mean it is stalled. Its fixed
6,000-second horizon is simulated time, not a wall-clock timeout.

## Run in separate sessions

To complete and save the regression before the campus run, use the same output
directory and the same MATLAB release/version for each command:

```matlab
report = run_tranche17_validation(fullfile(pwd,'results','t17'), struct('Phase','tests'));
report = run_tranche17_validation(fullfile(pwd,'results','t17'), struct('Phase','campus'));
report = run_tranche17_validation(fullfile(pwd,'results','t17'), struct('Phase','finalize'));
```

Each completed stage has a receipt binding its source, references, runtime and
outputs. The default command can also reuse verified completed stages. This
does not resume a partially simulated campus run. If a stage fails or is
interrupted, preserve that output directory and return its partial ZIP if one
was produced. A fresh attempt uses a new output directory, for example
`results/t17b`; do not delete failed evidence to make a directory reusable.

## What this milestone establishes

Successful execution provides a full portable test result and one current
campus measurement. Review checks application accounting, admission pressure,
control traffic, retries, per-flow delivery and delay, and compares the exported
60-second aggregates with pinned ns-3 and archived OPNET evidence. Source
differences and stochastic numerical differences remain explicit.

Pending work at the finite stop is reported. Admission counters cover every
attempt; the established 100,000-record admission trace limit is retained and
omissions are reported. Protocol and PHY trace omissions fail the structural
gate. No extra draining period is added.

This candidate has not been executed in MATLAB here. It introduces validation
and reporting files; all 304 Tranche 16 source bindings, including 155 MATLAB
files, are preserved byte for byte. It makes no PHY/ECC or timing-policy change.
Passing this gate does not by itself establish numerical parity. The returned
campus flow and service differences will select the next bounded parity fix.

See `docs/tranche-17-spec.md` for architecture, provenance and review details.
