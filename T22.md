# Tranche 22: controlled adaptive-window replay

T22 tests whether identical controlled sends, transmit notifications and
ACK/DACK feedback produce the same HOP admission-window state in MATLAB and
the pinned ns-3 implementation. It follows T21's finding that different window
histories accompany the node 8 congestion gap.

Copy your **accepted T20 installation** to a short path such as `C:\csr22`.
Extract every file from `t22up.zip` over that copy, replacing files if prompted.
T21 was an analysis package; it does not need to be installed.

Run from the copied installation folder in MATLAB:

```matlab
clear functions
report = run_tranche22_validation;
```

This runs nine short controlled HOP cases, records 364 action checkpoints, and
runs 89 focused tests listed in `evidence/tranche-22-candidate.json`. It does
not run the 6,000-second campus simulation. The accepted production code,
actual-tx default, continuous timing and PHY/ECC remain unchanged.

Upload the **`t22.zip`** whose full path MATLAB prints at the end. Each run uses
a fresh folder beneath `results/t22/`. Return the ZIP even if a test fails;
the runner preserves completed test results and replay checkpoints for review.

The native reference was built from the pinned production HOP implementation.
MATLAB execution of this new candidate remains pending until your run. A local
pass still requires independent return review.

The ±10% working goal applies to campus performance comparisons. This test
requires exact agreement in discrete HOP states, with a 1 ns tolerance for the
recorded action time. It is a controlled callback test, not a PHY or end-to-end
security test and not evidence of improved campus delivery.

See `docs/tranche-22-adaptive-window.md` for case coverage and limitations.
